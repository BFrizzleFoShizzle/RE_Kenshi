# RE_Kenshi Privacy Policy

*Last updated: 5/9/26*

RE_Kenshi is free and open-source software. It does not collect or transmit
any data during normal use. The only time RE_Kenshi sends data anywhere is
when reporting crashes, install errors, or bugs, and only with your
explicit input at that time.

## What is sent, and when

There are three separate report types. Nothing is sent unless you choose
"Send Report" (or equivalent) in the relevant dialog.

**Automatic crash report** (shown if RE_Kenshi crashes):
- The Kenshi and RE_Kenshi version numbers
- RE_Kenshi's settings file (`RE_Kenshi.ini`)
- RE_Kenshi's log file (`RE_Kenshi_log.txt`)
- Kenshi's crash dump archive, including any log and configuration files
  Kenshi automatically includes in it. The archive may incidentally
  contain file paths, your Windows username, or other data that happened
  to be in memory at the time of the crash
- The bug description you write in the crash report window
- Optionally, a hash of a machine identifier (see below)

**Manual bug report** (available any time via RE_Kenshi's settings menu):
- The Kenshi and RE_Kenshi version numbers
- The bug description you write
- Optionally, a hash of a machine identifier (see below)

**Installer error report** (shown if RE_Kenshi's installer encounters an error):
- The installer version
- The window and installation step the error occurred in
- The installer's log (viewable via "Show Details" before sending)
- The error message
- The installer log may incidentally contain file paths, your Windows
  username, or other system information recorded during installation
- Optionally, a hash of a machine identifier (see below)

## The optional machine identifier

Each report dialog includes a checkbox to include a hash of your machine's
Windows install UUID. This value is generated by Windows itself at install
time — it is not tied to your physical hardware and is not personally
identifying on its own.

Including it lets the developer:

- Recognize when multiple reports come from the same machine, which helps
  with debugging recurring issues
- Look up a specific report later, if you contact the developer and refer
  to it

If you leave the checkbox unchecked, your report is sent without this
identifier. In that case, the developer has no practical way to find,
link, or delete that specific report later.

## Where reports are stored

Reports are sent to a private Discord server accessible only to the
developer, via a one-way webhook (which allows posting to the server but
not reading anything from it). Discord is a third-party service operated
outside New Zealand, and data sent to it is also subject to Discord's own
privacy policy and infrastructure.

## How long reports are kept

Reports are kept for a maximum of 3 years from the date they're submitted,
after which they are deleted.

## Accessing or deleting your data

If you included the machine identifier when you sent a report, you can
contact the developer (details below) with that identifier to ask about,
or request deletion of, your reports.

If you did not include the identifier, the developer generally has no
practical way to locate a specific report among the others held, since
such reports are not otherwise individually identifiable.

## Aggregate crash statistics

Kenshi's own code is responsible for the large majority of crashes seen in
crash dumps. RE_Kenshi's developer uses a tool that processes crash dumps
into aggregated, anonymized stack trace summaries, showing only which
functions in Kenshi's code commonly appear on the stack when a crash
occurs, with all other data stripped out — mainly to help identify common
crash causes. These summaries do not identify, and cannot be traced back
to, any individual or machine.

The developer may, at their own discretion, choose to share these
anonymized summaries with Kenshi's original developers in the future, to
help highlight bugs in the base game. This is not a current, ongoing
practice, and RE_Kenshi's developer is not affiliated with, and does not
act on behalf of, Kenshi's original developers. This does not apply to
your original crash dump, settings, logs, or bug description, which are
not shared beyond RE_Kenshi's developer without your explicit consent (see
below).

## Sharing a report with a third-party plugin developer

RE_Kenshi supports third-party plugins. If a plugin developer asks the
developer to help debug an issue, the developer may forward a copy of a
specific crash report to that plugin developer, but only at the explicit
request of the person who submitted it, and only after reasonably
confirming their identity (for example, by asking them to provide the
machine identifier hash associated with that report). Report contents
(including any incidental personal information, per the sections above)
are not otherwise shared with plugin developers or any other third party.
Plugin developers are independent of RE_Kenshi and are not bound by this
policy; any data forwarded to one is subject to their own handling
practices, which the RE_Kenshi developer does not control.
